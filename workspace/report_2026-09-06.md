## 三、关键发现与建议

### 严重问题

**1. 微信VOIP平台HTTP 500大规模爆发（81条，全新模式）**

- **现象**：09-06突然出现大量VOIP HTTP 500错误，分为两类：
  - ResourceAllocationFailed（36条）："The request could not be fulfilled because resources could not be allocated"
  - ServiceUnavailable（30条）："The service is temporarily unavailable. Retry later."
  - TaskConflict（12条）："A session with the same name already exists"（持续存在）
  - InternalError（3条）："An unexpected internal error occurred"
- **根因**：微信VOIP平台侧资源不足或服务降级，**非本地服务问题**
- **影响**：所有微信小程序VOIP通话发起请求受影响（ResourceAllocationFailed + ServiceUnavailable合计66条）
- **判断**：VOIP平台可能在进行扩容/缩容、维护或遭遇流量高峰
- **建议**：
  1. 联系微信VOIP平台确认是否有维护公告或资源紧张
  2. 检查这66条错误的分布时段，判断是否集中在某一时间段（如晚高峰）
  3. 确认代码侧是否已实现指数退避重试机制（微信VOIP建议：初始重试间隔1s、2s、4s，最大3次）
  4. 持续监控次日是否持续或自愈

**2. NoneType.stream错误持续存在（108条，稳居Top 1）**

- **现象**：两个API端点各54条，合计108条，占全天Error的25.4%
  - /api/session/news/ip-dialog-info：54条
  - /api/session/user/statistics：54条
- **根因**：下游服务返回None，代码缺少 if response is not None 防护
- **趋势**：从前天152条降至108条（-28.9%），有所改善但仍高位运行
- **影响**：app.controllers.weapp_index 连续多日为Top 1或Top 2 Logger
- **建议**：
  1. **最高优先级代码修复**：在 weapp_index.py 对应方法中增加None检查
  2. 确认下游服务（可能是ling-smart-svc或TTS服务）是否返回None
  3. 如果下游服务频繁返回None，应排查下游服务健康状态

### 中等问题

**3. 晚高峰Error集中（18:00-20:00共204条，+90.7% vs 前天）**

- **19:00峰值109条**：root(48条) + exception_handlers(34条) + voip(15条)
- **18:00为59条**：主要由VOIP错误和NoneType.stream驱动
- **根因**：晚高峰用户VOIP通话请求增加 + 微信VOIP平台资源紧张
- **建议**：如果VOIP问题持续，考虑在VOIP发起前增加平台可用性预检

**4. Internal Server Error仍为第3大错误（48条）**

- 来自 app.exception_handlers，包含Unhandled和已处理的ISE
- 其中2001001304内部错误43条，通常是业务层异常未完全拦截
- 从前天62条降至48条（-22.6%），趋势向好
- **建议**：关注ISE的内部结构变化，如裸ISE（无业务错误码）是否增加

**5. Coze平台间歇性500错误（6条）**

- 错误消息："We're currently experiencing server issues."
- 前天4条 → 昨天6条，Coze平台侧问题，非本地服务
- **建议**：确认Coze调用是否有重试+退避机制
