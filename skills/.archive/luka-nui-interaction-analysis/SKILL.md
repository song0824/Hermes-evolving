# Luka NUI 交互问题分析

## 背景
Luka LLM 新版本上线后，6岁儿童使用读书功能出现严重交互问题，孩子"用不起来"。核心原因：LLM 开放性理解替代了老版本确定性对话树，且缺乏对儿童行为节奏的 timing 控制。

## 三大核心问题

### 1. 零引导 — 孩子不知道怎么用
- 孩子拿起 Luka 直接说「给我读书」
- 老版本：固定意图匹配 → 明确指令「好的，请把书放在我面前」(<10字)
- LLM版本：意图理解偏差 → 回复冗长复杂，6岁听不懂
- 结果：孩子无法建立交互预期

### 2. 等待耐心不足 — 打断/拍头
- LLM 生成时间 3-10s+（老版本固定1-2s）
- 6岁儿童无法耐心等待，会焦急打断、拍头
- Luka 被打断后 LLM 重新生成，更慢 → 恶性循环
- 结果：Luka 根本话都说不完整

### 3. 翻页识别节奏不匹配 — 重复读上一页
- 孩子翻页速度：3-8秒/页（慢）
- 老版本识别间隔：4-5s（经调优匹配儿童节奏）
- LLM版本识别间隔：1-2s（太短，未针对儿童调优）
- 结果：孩子没翻完就重复读上一页 → 着急拍头 → 打断 → 更慢

## 三种模式时间序列对比

| 维度 | 老版本 | LLM新版本 | 小方机Facetime |
|---|---|---|---|
| 意图识别 | 固定意图匹配 ✅ | LLM理解 ❌ | 语音+LLM ❌❌ |
| 响应时间 | 1-2s固定 | 3-10s+不稳定 | 3-10s+网络延迟 |
| 回复长度 | <10字固定 | 冗长不定 | 冗长不定 |
| 翻页间隔 | 4-5s ✅ | 1-2s ❌ | 1-2s+举书不稳 ❌❌ |
| 打断恢复 | 固定策略 ✅ | LLM重建慢 ❌ | 更难 ❌❌ |
| 可预期性 | 高，2-3次学会 | 低 | 极低 |
| 体力负担 | 书放设备上 ✅ | 书放设备上 ✅ | 举书对镜头 ❌ |

## 关键改进建议

1. **意图引导前置**：首次使用强制进入教学引导流程，不交给LLM自由回复
2. **翻页检测冷却时间**：识别到新页后至少等 4-6s，或检测到画面稳定后再触发
3. **LLM回复长度限制**：读书场景下LLM回复控制在15字以内
4. **打断固定策略**：检测到打断不触发LLM重新生成，用固定短句安抚+恢复
5. **Facetime特殊模式**：视频通话场景切换为"短时朗读+确认翻页"模式，减少举书负担

- LLM响应超时设置
